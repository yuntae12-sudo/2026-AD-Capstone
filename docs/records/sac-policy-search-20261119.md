# SAC 주행 정책 확보 작업 — 2026-11-19

사용자는 2~3일이 걸려도 실제 주행 가능한 정책을 실험·검증·실패 분석을 반복하며
확보하는 작업을 요청했다. 시간은 허용한 작업 규모이며 성공 시한이나 무중단 실행을
보장한 것이 아니다. [이전 두 후보](sac-replay-coverage-20261118.md)는 채택하지 않았다.

## 유지할 조건과 완료 판정

- 주 비교는 Rule-based vs 순수 SAC다. BC와 teacher replay를 도입하지 않는다.
- 보상·관측·명령·30점 경로·충돌/물리 검사·공통 PD와 데이터 분리를 유지한다.
- B 평균은 기존 승인 범위의 별도 비교다. 새 설정을 기본 설정으로 자동 채택하지 않는다.
- 실험 중 설정·데이터·코드를 바꾸지 않는다. 다른 후보는 새 출력 폴더와 provenance로
  구분하고, 이전 실패 결과도 남긴다. 오류와 실제 정책 실패를 구분한다.
- Q 손실 감소나 몇 개 초기 경로의 검사 통과만으로 완료하지 않는다.

이번 반복의 작업 확대 기준과 최종 목표 제안을 아래에 기록한다. 사용자 확정 성능
수치로 취급하지 않으며, 안전검사 한계나 SAC 수학 규약의 변경도 아니다.

1. 동일한 빠른/저속 두 장면 KEEP/FOLLOW에서 초기 정책이 성공한 빠른 두 주행의
   성공을 보존한다. 저속 두 실패도 평가에서 제외하지 않는다.
2. 개발 validation8개×KEEP/FOLLOW 전체를 평가한다. 초기 정책 대비 성공·충돌이
   개선되고, 정지·제동으로 지표가 좋아 보이는 현상이 없는지 함께 확인한다.
3. 최종 목표는 동일 조건 Rule-based보다 성공률이 낮지 않고 충돌률이 높지 않은
   정책이다. 현재 기준선은 성공7/16·충돌8/16으로 그 자체가 완벽한 주행은 아니다.
   거절·제동·정지·보상·KEEP/FOLLOW별 상충도 공개한다.
4. seed0/1/2를 모두 평가하고 가장 좋은 seed만 대표로 고르지 않는다. 후보 선택에
   사용하지 않은 별도 장면을 정책 결과와 무관하게 확보한 뒤 같은 비교를 수행한다.
   추가 장면 확보 목표는 기존 운영 기준의32개이며 아직 확보한 수가 아니다.
5. 최종 결과 표, 실패 목록, Rule-based/SAC 비교 GIF, 설정·가중치·데이터 해시를 남긴다.

최종 목표를 달성하지 못하면 정책 확보 완료로 표시하지 않는다. 작은 개발 표본의 성공을
실도로 안전성 또는 모든 상황에서의 완벽한 동작으로 주장하지 않는다.

## 반복 절차

1. 실패에 대한 검증 가능한 가설 하나를 정하고 대조군·예산·판정 기준을 먼저 기록한다.
2. 수치/규약 검사 → 고정 상태 진단 → 짧은 실제 온라인 학습 → 실제 주행 순서로 검증한다.
3. 실패한 후보를 채택하거나 동일 설정으로 무작정 장기 학습하지 않는다. 실패 증거를
   보고 다음 변경을 결정한다. 학습 절차나 목적함수를 바꾸는 경우 별도 개정으로 명시한다.
4. 짧은 주행 회귀를 통과한 후보만 전체 validation, 나머지 seed, 별도 평가로 확대한다.

백그라운드 프로세스는 지정한 학습·평가를 실행하고 로그/복구본을 저장할 수 있다.
이것이 대화 종료 후에도 분석과 소스 수정이 자동으로 계속되는 에이전트라는 뜻은 아니다.
실행 완료 여부와 다음 판단을 구분해 기록한다. 새 PR을 후보마다 만들지 않는다.

## 첫 반복: Critic 적합과 일반화 분리

`scripts/diagnose_sac_critic_generalization.py`를 추가했다. 기존 자체 warmup5,000개에서
bootstrap=False인62개 전이를 사용하므로 저장 행동의 정답은 실제 immediate reward다.
장면 단위로 fit/holdout을 분리하고, 기존 두 반례 장면은 fit 쪽에 고정한다. 같은 장면의
KEEP/FOLLOW를 양쪽으로 나누지 않는다.

이전 Waymax 재현에서 실제 terminal 결과가 확인된 네 행동(두 상태×두 정책 평균)을
새 행동 검사에 사용한다. 다른 행동의 보상을 저장 행동과 같다고 가정하지 않는다.
이 네 행동은 이전 실패로 선택한 반례이며 모집단 대표 표본이 아니다.

seed0에서 동일한500회 예산의 네 supervised 진단을 비교했다.

| 진단 | 초기값 / 학습 자료 | 확인할 내용 |
|---|---|---|
| continued_records | 기존1,000회 후보 critic / fit의 저장 행동 | 기록 행동 오차를 더 줄여도 새 행동의 오차가 남는가 |
| fresh_records | 새 critic / 같은 저장 행동 | 기존 학습 경로와 무관한 적합·일반화 여부 |
| fresh_zero_action_init | 새 critic의 첫 Dense 행동 입력60행만0 초기화 / 같은 저장 행동 | 행동보다 상태를 먼저 구분하는 초기화의 영향 |
| fresh_plus_one_action_per_probe_scene | fresh와 동일 / 각 반례 상태의 확인된 대체 행동1개 추가 | 실제 행동 다양성을 더하면 다른 확인된 행동으로 일반화되는가 |

마지막 진단은 추가한 행동과 학습에 넣지 않은 행동을 분리해 해석한다. continued 진단은
이전 SAC에서 holdout 장면을 이미 보았으므로 새로운 장면 일반화 실험이라고 부르지 않는다.
fresh 진단만 이 supervised 학습의 장면 분리를 만족한다.

이는 terminal-only 지도 회귀 **진단**이다. SAC 업데이트·정책 학습·critic 사전학습의
채택이 아니며, 이 진단 가중치를 실제 정책 학습에 넣거나 production checkpoint로
저장하지 않는다. actor·target·alpha·replay·기존 checkpoint를 변경하지 않는다.

실행 자료: `outputs/sac_policy_search_20261119/critic-generalization/`.
명령/PID는 `critic-generalization-launch.json`, 진행 내용은 `critic-generalization.log`와
원자적으로 저장되는 `report.json`에 기록한다. 완료 결과는 아래에 기록한다.


### 첫 진단 완료 결과

54개 전이·40개 장면으로 적합하고8개 전이·6개 장면을 별도로 검사했다.
500회 후 두 critic의 min Q 기준 평균 절대 오차는 다음과 같다.

| 진단 | fit 기록 행동 | 별도 장면 기록 행동 | 학습에 넣지 않은 확인된 대체 행동 |
|---|---:|---:|---:|
| continued_records | 0.00016 | 0.03577 | 10.54210 (4개) |
| fresh_records | 0.00012 | 0.26454 | 0.63299 (4개) |
| fresh_zero_action_init | 0.00041 | 0.22445 | 0.12609 (4개) |
| fresh_plus_one_action_per_probe_scene | 0.00048 | 0.47255 | 0.05873 (2개) |

continued의 별도 장면 열은 이전 학습 노출이 있어 일반화 결과가 아니다. 추가 행동을
넣은 진단의 대체 행동 열은 넣지 않은2개만 집계했고, 나머지는4개다. 오차가 작다는
결과는 제한된 terminal 회귀 진단이며 전체 Bellman Q나 실제 주행 성공을 인증하지 않는다.

기존 critic은 기록 행동 오차를 거의0으로 만들어도 다른 행동에서 큰 오차가 남았다.
새 critic에서는 같은 구조로 오차가 크게 줄어 네 반례의 표현이 불가능한 것은 아니었다.
초기 학습 과정과 행동 의존성의 영향을 실제 온라인 SAC로 확인할 근거다.

## 다음 제한 실험: 행동 입력0 초기화

두 critic 첫 Dense의 마지막60개 행동 입력 행만0으로 시작하고 target에도 같은 값을
적용한다. 이후 이 행도 원래 SAC gradient로 학습한다. actor·sigma·보상·검사·PD·uniform
replay·업데이트 비율·학습률·Q 목적함수는 바꾸지 않는다. 기존 기준 배율은
`mean_gain=0.0012098536225957168`로 유지해 새 실험에서 배율을 추가 탐색하지 않는다.

이것은 새 초기화 비교이며 기존 정책 가중치를 수술한 것이 아니다. 앞의 supervised
가중치는 재사용하지 않고 actor/critics를 새로 초기화한다. 주 실험의 기본 초기화는
유지하며 진단 CLI `--zero-critic-action-init`에서만 활성화한다. actor·optimizer·RNG 보존,
Q/target 동기화, 이후 행동 의존성 학습 가능 여부를 테스트한다.

먼저100회 온라인 업데이트와 동일4주행을 검사한다. 초기 성공 장면 회귀가 있으면
1,000회로 확대하지 않는다. 통과하면 새 learner의 같은 초기화로1,000회 제한 실행을
하고, 같은 주행과 Q 반례를 다시 확인한다. 이 짧은 반복 결과를 확보하기 전에는
장시간3-seed 실행을 예약하지 않는다.


### 자동 실행 범위

`scripts/run_sac_initialization_trial.py`는 완료된100회 산출물을 받아 다음 작업을
조건부로 연결한다.

1. 같은4주행을 평가하고, 초기 정책의 성공 장면이 모두 성공하는지 및 충돌 수가
   증가하지 않았는지 확인한다. 장면/명령/seed/초기 frame/map도 일치해야 한다.
2. 통과 시 새 learner로 같은 조건의1,000회 학습과 같은4주행 평가를 수행한다.
3. 다시 통과하면 두 고정 Q 반례 및 전체 validation을 평가한다.
4. 회귀는 `COMPLETE_WITH_REGRESSION`, 실행 오류는 `FAILED`, 모든 실행을 마친 경우도
   `COMPLETE_PENDING_REVIEW`로 기록한다. 어느 상태도 정책 채택/최종 목표 달성을 뜻하지 않는다.

빈/누락/중복 평가로 기준을 통과할 수 없고, 입력 및 실행 소스 hash가 변하면 중단한다.
각 작업의 명령·로그·결과 hash와 gate를 보존하며 단일 작업 timeout은2시간이다.
이 실행기는 새 가설을 선택하거나 소스를 자동 수정하지 않는다.

실행 폴더는 `outputs/sac_policy_search_20261119/zero-action-trial/`이다.
100회 학습 자체는 완료했고, 후속 자동 실행 상태는 이 폴더의 `report.json`을 따른다.


### 검증 기록

새 초기화의 target 동기화·actor/optimizer/RNG 보존·행동 gradient 학습 가능 여부,
장면 단위 holdout 분리, 빈/누락/중복/회귀 평가의 확대 차단을 검사했다. 관련 고유9개
테스트 통과(새4개, 기존 단기 변형5개). 처음 초기화 테스트는 모든 관측이 invalid인
빈 schema fixture에서 ReLU가0에 머물러 실패했고, 실제 학습처럼 valid ego 관측을
포함하도록 fixture를 수정한 뒤 통과했다. 이 실패를 실제 도로 정책 실패로 분류하지 않는다.

실제 GPU100회 학습은 유한성 검사와 raw action/replay 저장 대조까지 완료했다.
전체 테스트·새3-seed 학습·독립 test 성능 검증은 아직 수행하지 않았다.


### 100회 실제 주행 완료 및 다음 실행

고유2장면×KEEP/FOLLOW4episode에서 빠른 두 주행은 각각72tick ROUTE_GOAL,
저속 두 주행은 각각37tick COLLISION이었다. 초기 정책은 각각72/72/36/36tick이므로
성공 수2/4·충돌 수2/4를 유지한 것이며 학습 개선을 입증하지 않았다.
빠른 주행은 각각 거절11·제동8·정지0tick, 저속 주행은 각각18·15·11tick이었다.
초기 frame/map/seed와 성공 유지·충돌 수 검사를 통과했다.

조건부 실행기는 `train1000` 단계로 넘어갔다. 이는 첫100회 가중치를 재개하는 것이
아니라 같은 자체 warmup과 새 learner에서 시작하는1,000회 비교다. 아직1,000회 주행
결과나 최종 정책 성능을 확인한 것은 아니다. 최신 상태는 실행 폴더의 report를 우선한다.
